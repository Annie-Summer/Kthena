# 端到端架构：规格推荐 → Kthena 部署 → 预测弹性扩缩容

## 1. 总体架构（总览）

```text
                         ┌──────────────────────────────────────┐
                         │              输入                     │
                         │  模型  +  场景  +  QoS(TTFT/TPOT等)   │
                         └──────────────────┬───────────────────┘
                                            │
                                            ▼
┌───────────────────────────────────────────────────────────────────────────┐
│                     ① 算力规格推荐平台                                      │
│                                                                           │
│   判定 PD： 聚合 ────────────────┐     分离 ───────────────┐               │
│                                  ▼                        ▼               │
│                        一套整体方案              P 方案 + D 方案            │
│                                                                           │
│   大模型：卡型/卡数 + TP/PP/DP/EP                                          │
│   小模型：AIcore% + 显存 (FlexNPU)                                        │
│                                                                           │
│   同时落盘 InstanceProfile：单实例产能@QoS、t_ready、并行/包装、扩缩单位     │
└───────────────────────────────────┬───────────────────────────────────────┘
                                    │
                                    ▼
┌───────────────────────────────────────────────────────────────────────────┐
│                     ② 布局规划 + 部署清单生成                               │
│                                                                           │

│   小模型：实例数 → Pod 数；填写 FlexNPU 算力/显存                           │
│                                                                           │
│   生成：ModelServing YAML                                                  │
│         PD 分离时另附 ModelServer / ModelRoute (+ KV)                      │
└───────────────────────────────────┬───────────────────────────────────────┘
                                    │  apply
                                    ▼
┌───────────────────────────────────────────────────────────────────────────┐
│                     ③ Kthena 部署与拉起                                     │
│                                                                           │

│        │                                                                   │
│        ├─ 注入 WORKER_INDEX / GROUP_SIZE / ENTRY_ADDRESS                   │

│                     ④ 在线推理                                              │

│                         │                                                 │
│                         ├─ PD 聚合：实例内多 Pod 协同前向                     │

│        ▼                                                                   │
│   换算：预测负载 ÷ InstanceProfile.单实例产能  →  desired 实例数              │

共享内核：InstanceProfile（规格推荐写出，预测弹性读取）

  - 扩缩单位：ServingGroup 或 prefill/decode Role
```

## 3. PD 聚合 vs 分离（推荐与部署）

```text
PD 聚合                              PD 分离
────────                             ────────
推荐：1 套方案                        推荐：P 一套 + D 一套
  │                                    │
  ▼                                    ▼
ModelServing                         ModelServing
  Role: infer                          Role: prefill
    Entry + Workers                      Entry + Workers
                                       Role: decode
                                         Entry + Workers
                                       + ModelServer / Route + KV

弹性：改 ServingGroup 数              弹性：P、D 副本分别预测与扩缩
```

## 4. 数据流：从部署到预测扩缩

```text
[模型+场景+QoS]
      │
      ▼
[规格推荐] ──Profile──┐
      │               │
      ▼               │
[Pod布局+YAML]        │
      │               │
      ▼               │
[Kthena部署] → Ready → [Router接流量]
      │                       │
      │                       ▼
      │               [采集 req / tokens]
      │                       │
      │                       ▼
      │               [预测未来负载]
      │                       │
      └────产能───────► [÷单实例产能 → 目标实例数]
                              │
                              ▼
                      [Autoscaler 扩缩]
                              │
                              └──► 再进入 Kthena/Volcano 拉起或回收
```

## 5. 自动化边界

| 环节 | 自动化目标 |
| --- | --- |
| 规格推荐 | 输出结构化方案 + InstanceProfile（含 PD 模式） |
| 布局生成 | 由推荐自动算 Pod/资源并渲染 YAML |
| 部署拉起 | apply → 注入 rank → 调度 → load → Ready |
| 在线路由 | Router 分配到模型实例 |
| 预测弹性 | 采集→预测→按 Profile 换算→Autoscaler 执行 |

当前常见缺口在「推荐 → Pod/YAML」；产品需补齐布局规划器与清单生成器，并与预测弹性共享 Profile，才能端到端全自动。
