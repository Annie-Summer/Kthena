# 端到端架构：规格推荐 → Kthena 部署 → 预测弹性扩缩容

## 1. 总览架构（一屏）

PNG：[`e2e-overview.png`](./e2e-overview.png)

```text
 模型+场景+QoS
        │
        ▼
 ┌──────────────────┐  大模型: 卡+TP/PP/DP/EP     ┌─────────────────┐
 │ ① 规格推荐        │  小模型: AIcore+显存        │ InstanceProfile │
 │  PD聚合|分离      │ ─────────────────────────► │ 单实例产能@QoS   │
 └────────┬─────────┘                             └────────▲────────┘
          │ 方案                                            │ 复用
          ▼                                                 │
 ┌──────────────────┐     ┌──────────────┐     ┌──────────┴──────────┐
 │ ② 布局+生成YAML   │────►│ ③ Kthena部署 │────►│ ④ Router→模型实例   │
 │ 算Pod / FlexNPU  │     │ 注入rank     │     │ 聚合协同 / P→KV→D   │
 └──────────────────┘     │ Volcano调度  │     └──────────┬──────────┘
                          │ 分片load→Ready│                │ req/tokens
                          └──────▲───────┘                ▼
                                 │            ┌───────────────────────┐
                                 └────────────│ ⑤ 预测弹性             │
                                   改replicas │ 预测÷产能→实例数       │
                                              │ Autoscaler(+实时兜底)  │
                                              └───────────────────────┘
```

要点：①定实例形态与产能；②补齐 Pod 清单；③④部署与接流；⑤用同一 Profile 做预测扩缩。

## 3. PD 聚合 vs 分离（推荐与部署）

```text

────────                             ────────

  │                                    │
  ▼                                    ▼
ModelServing                         ModelServing
  Role: infer                          Role: prefill
    Entry + Workers                      Entry + Workers
                                       Role: decode
                                         Entry + Workers
                                       + ModelServer / Route + KV

```

## 4. 数据流：从部署到预测扩缩

```text
[模型+场景+QoS]
      │
      ▼
[规格推荐] ──Profile──┐
      │               │
      ▼               │
[Pod布局+YAML]        │
      │               │
      ▼               │
[Kthena部署] → Ready → [Router接流量]
      │                       │
      │                       ▼
      │               [采集 req / tokens]
      │                       │
      │                       ▼
      │               [预测未来负载]
      │                       │
      └────产能───────► [÷单实例产能 → 目标实例数]
                              │
                              ▼
                      [Autoscaler 扩缩]
                              │
                              └──► 再进入 Kthena/Volcano 拉起或回收
```

## 5. 自动化边界

| 环节 | 自动化目标 |
| --- | --- |
| 规格推荐 | 输出结构化方案 + InstanceProfile（含 PD 模式） |
| 布局生成 | 由推荐自动算 Pod/资源并渲染 YAML |
| 部署拉起 | apply → 注入 rank → 调度 → load → Ready |
| 在线路由 | Router 分配到模型实例 |
| 预测弹性 | 采集→预测→按 Profile 换算→Autoscaler 执行 |

当前常见缺口在「推荐 → Pod/YAML」；产品需补齐布局规划器与清单生成器，并与预测弹性共享 Profile，才能端到端全自动。
